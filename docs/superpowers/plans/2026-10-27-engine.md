# AURA Engine Full Scope Implementation Plan

> Required: Superpowers executing-plans, test-driven-development and verification-before-completion; Codex Engineering Guardrails. Owner authorised full implementation without check-ins.

**Goal:** An extensible production-oriented local engine that can execute real authorised tasks via Termux CLI, Android ADB, filesystem, skills and cloud models with secure Android-facing RPC, persistent state, recovery and economy.

**Architecture:** Standard-library Python local HTTP adapter; SQLite job/event store; process executor boundary; provider adapters; workspace isolation; explicit risk approvals. The Android UI is developed separately by Claude Design Systems, using docs/ENGINE_CONTRACT.md.

**Tech:** Python >=3.12, SQLite, Android Termux, official Claude/Gemini CLIs, `gh`, `adb`, official API endpoints.

## Source of truth
`README.md`, `AGENTS.md`, `docs/PRODUCT_SPEC.md`, `docs/CONSTRAINTS.md`, `docs/ENGINE_CONTRACT.md`; repository main is canonical.

## Execution ledger
A task is complete only if its related test fails before implementation then passes after on canonical SHA. CI green != full Android system verification. Any blocking item must be recorded explicitly rather than silently substituted by a mock.

## Stop conditions
No installing unreviewed binaries, no deleting repos/files in a smoke test, no writing any device/ECU during verification, no OAuth secrets in repository, no remote-execution substitution.
